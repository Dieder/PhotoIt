# Photo It

Photo It is a .NET 10 Blazor application for organizing travel photos into albums, arranging them into a paged photo-book layout, and sharing the finished album. Photo descriptions and tags are generated by a vision model running locally on the application host.

## Features

- Create and edit albums with a name, description, and Markdown introduction.
- Upload and manage album photos. Images are stored in Azure Blob Storage; the app extracts available EXIF metadata such as capture date, camera, and GPS coordinates.
- Generate a concise description and searchable tags for album photos with the local vision model. Tags can be filtered in the photo manager.
- Design multi-page album layouts with a title/cover page, selectable page templates, and draggable photos; preview the result as a presentation.
- Create a share link for an album layout so it can be viewed without signing in.
- Edit a trip route by entering places and transport types; place names are resolved using OpenStreetMap Nominatim.
- Use ASP.NET Core Identity for account and album-owner features.

## Local photo tagging

The web application uses **Phi-3 Vision through ONNX Runtime GenAI**. It loads the model files from `VisionModel:ModelDirectory` on the application machine; model files are not downloaded automatically. The background indexing service loads the model when the app starts. After an album photo is uploaded, its ID is queued and the service downloads the image from Azure Blob Storage, runs inference locally, and saves the description, tags, and indexing time with the album photo. Inference is performed by the server, not in the browser or by a hosted vision API. The photo itself remains in Azure Blob Storage.

Photo management is available while the model loads. Once it is ready, album owners can use **Index tags with vision model** to index photos that do not already have tags. The model returns JSON containing a concise description and useful lowercase tags; those tags can then be used with the photo tag filter. Model loading and inference require a compatible Phi-3 Vision ONNX Runtime GenAI model directory.

## Architecture

The solution is split into these main projects:

| Project | Responsibility |
| --- | --- |
| `PhotoIt.Web` | Interactive Server Blazor UI, Identity, album/photo workflows, HTTP endpoints, and dependency registration. |
| `PhotoIt.Data` | Album and layout models, LiteDB catalogs, photo metadata extraction, and Azure Blob Storage integration. |
| `CleanCode.AiOrgestation` | Coordinates vision analysis with album data and runs the background photo-indexing queue. |
| `AiFoundryLocal` | Local Phi-3 Vision ONNX Runtime GenAI inference and local-file indexing support. |
| `PhotoIt.Core` | Shared route/geolocation services, including the Nominatim client. |
| `PhotoIt.ServiceDefaults` | Shared .NET Aspire service defaults, health checks, and observability integrations. |
| `PhotoIt.AppHost` | .NET Aspire host that launches the web app and API service together. |
| `CleanCode.ApiService` | Separate minimal API project; its current endpoints are a sample root status and weather forecast, not the album or tagging API. |

The web app uses SQLite via Entity Framework Core for Identity (`AlbumWebContext.db`) and LiteDB for album, photo, and layout data (`PhotoIt.Web/App_Data/albums.db`). The local file-tag catalog is configured at `PhotoIt.Web/App_Data/photo-tags.db`. Original album images are stored in Azure Blob Storage. Photo uploads enqueue work for a hosted service, which calls `PhotoVisionOrchestrator` and persists the resulting description and tags.

## Requirements

- .NET 10 SDK.
- An Azure Storage account with Blob data permissions for the app. The app creates the configured private container if it does not exist.
- A local Phi-3 Vision model directory compatible with ONNX Runtime GenAI. Set its path before starting the web app.
- Network access to OpenStreetMap Nominatim for place-name lookup in the route editor.

## Configuration

The web app reads settings from `PhotoIt.Web/appsettings.json`, environment variables, and .NET user secrets. The checked-in appsettings file contains sample/default values; update them for your environment. The following settings are consumed by the current web app:

| Setting | Required | Purpose |
| --- | --- | --- |
| `ConnectionStrings:AlbumWebContext` | Yes | SQLite connection string for Identity. Defaults to `Data Source=AlbumWebContext.db`. |
| `AzureStorage:AccountName` | Yes, unless derived from `AccountUri` | Azure Storage account name. |
| `AzureStorage:AccountUri` | No | Blob service URI; if omitted, it is built from the account name. The account name can also be derived from this URI. |
| `AzureStorage:ContainerName` | No | Blob container for photos. Defaults to `photos`. |
| `photostorageaccountkey` | No | Optional root-level configuration value for a storage account key. If omitted, the app uses `DefaultAzureCredential` (for example, an Azure CLI login in development or a managed identity when deployed). Prefer identity-based access where possible. |
| `VisionModel:ModelDirectory` | Yes for photo tagging | Path to the local Phi-3 Vision ONNX Runtime GenAI model directory. Relative paths are resolved from the web app's content root. The current default points outside the project directory; set it to where the model files are actually installed. |
| `VisionModel:MaxNewTokens` | No | Maximum generated output tokens; defaults to `128`. |
| `VisionModel:ContextLength` | No | Model context length; defaults to `4096`. |
| `VisionModel:LocalPhotoDirectory` | No | Root directory used by the local-file indexer; defaults to a `photos` directory under the web app. |

Example (replace the storage account and model path with values for your environment):

```json
{
  "ConnectionStrings": {
	"AlbumWebContext": "Data Source=AlbumWebContext.db"
  },
  "AzureStorage": {
	"AccountName": "<storage-account-name>",
	"AccountUri": "https://<storage-account-name>.blob.core.windows.net/",
	"ContainerName": "photos"
  },
  "VisionModel": {
	"ModelDirectory": "C:\\models\\onnx_phi3_vision\\cpu_and_mobile\\cpu-int4-rtn-block-32-acc-level-4",
	"MaxNewTokens": 128,
	"ContextLength": 4096
  }
}
```

For local development, set the model path without committing machine-specific values:

```powershell
dotnet user-secrets set "VisionModel:ModelDirectory" "C:\models\onnx_phi3_vision\cpu_and_mobile\cpu-int4-rtn-block-32-acc-level-4" --project PhotoIt.Web/PhotoIt.Web.csproj
```

If using a storage account key instead of `DefaultAzureCredential`, keep it out of source control and set it as a user secret:

```powershell
dotnet user-secrets set "photostorageaccountkey" "<storage-account-key>" --project PhotoIt.Web/PhotoIt.Web.csproj
```

`OpenRouteService` entries currently present in appsettings are not read by the application; route place lookup currently uses Nominatim. Google sign-in parameters are declared in the Aspire host, but the web project's current Google authentication registration still contains placeholder credential strings, so external Google sign-in needs that registration wired to configuration before use.

## Run locally

1. Configure Azure Storage access and point `VisionModel:ModelDirectory` to a compatible local model directory.
2. From the solution directory, run the Blazor application:

   ```powershell
   dotnet run --project PhotoIt.Web/PhotoIt.Web.csproj
   ```

   Alternatively, run `PhotoIt.AppHost` to launch the Aspire application host and its referenced services.

The app applies its Identity SQLite migrations at startup. The Azure Blob container and local model are initialized during startup, so missing model files or unavailable/unauthorized Azure Storage can prevent the app from starting.
